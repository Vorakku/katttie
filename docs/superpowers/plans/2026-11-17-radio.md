# Our Little Radio Implementation Plan

> Execute the supplied specification incrementally with Superpowers and Ponytail. The user authorized implementation of that specification, including automated tests. No commits or publication were requested.

**Goal:** A runnable two-person synchronized YouTube room for Windows and ngrok.

**Architecture:** React/Vite client and Express/Socket.IO server, shared Zod contracts, authoritative in-memory rooms. YouTube media stays in the official visible embed. One production origin.

**Tech Stack:** TypeScript, React, Vite, Tailwind, Express, Socket.IO, Zod, Vitest, Playwright.

**Spec:** `docs/OUR_LITTLE_RADIO_IMPLEMENTATION_PLAN.md`

## Global constraints
- Separate 24-byte-or-more host and guest secrets; only guest secret in copied invite fragment.
- Two roles, newest authenticated socket replaces previous socket for that role.
- Queue cap 50; idle empty expiry 12 hours; bounded rooms, input, rate limits and deduplication caches.
- Server receipt order, monotonically increasing revisions, idempotent mutations and end events.
- Three clock samples; recalibrate every 30 seconds; drift checks every 6 seconds, tolerance 1.5 seconds and cooldown 12 seconds.
- Visible player at least 200 by 200 pixels; local autoplay activation; no player-event broadcast loops.
- Server-side video-status lookup before queue add; missing key fails closed for public access.
- No accounts, database, media proxy, optional reactions, notes or visual extras.

## Review focus
- Role replacement and late async status lookup must never resurrect a superseded authenticated session.
- Concurrent/duplicate next and ended intents advance once; stale queue removals receive canonical state.
- Offline commands never replay on reconnect, and takeover never causes a reconnect battle.
- Autoplay/buffering/errors stay local; local activation never resets canonical playback.
- Credentials are stripped from address bar, safely stored per room, and excluded from telemetry/referrers.

## Decisions
- Work directly in the provided empty workspace; there is no Git history to isolate or commit.
- The supplied ready-for-implementation specification is the approved design; do not reopen settled choices.
- `requestId` is required on queue mutations too; destructive queue commands require `expectedRevision`.
- Next at final item pauses that item at its current canonical position.
- Missing API key rejects queue submissions unless explicitly enabled localhost-only prototype mode.
- Browser tests replace only the external YouTube SDK with a test fixture, never a production fake-player flag.
